DbContext・entity・relationを定義する

今回の課題

  • 目安時間：35〜45分
  • 前提：DIのscoped lifetime、classとproperty、nullable型を読める
  • 目的：EF CoreがC# objectとrelational databaseの対応を組み立てる入口を理解する

Codexがフェーズ4のTaskApiを作り、SQLite用のDbContext、二つのentity、 categoryとtaskの1対多relationを定義します。学習者はコードを手入力せず、C#のpropertyがdatabase model上で primary key、foreign key、column、navigationへどう対応するかを読み取ります。

今回はdatabase schemaをまだ作りません。C#側のmodelを定義してEF Coreが認識できることまでを扱い、 そのmodelからmigrationとSQLite databaseを作る作業は次の課題へ分けます。

DbContextは何を担当するのか

DbContextは単なるdatabase connectionではありません。どのC# classを永続化対象とするか、 propertyをどのcolumnとして扱うか、entity間をどのforeign keyで結ぶかというmodelを保持します。 runtimeではqueryを組み立て、databaseから読んだentityを追跡し、SaveChanges時に必要なSQLを生成する 作業単位にもなります。

entity instanceそのものがSQLを実行するActive Record形式ではありません。applicationはDbContextを通じて entity集合へアクセスします。このため、同じ業務処理で読んだentityと変更したentityを一つのcontextが追跡できるよう、 ASP.NET Coreでは通常、一つのHTTP requestに一つのDbContextを割り当てます。

TaskCategoryとTaskItemの1対多relation

一つのcategoryには複数のtaskを所属させられます。一つのtaskが参照できるcategoryは最大一つです。 categoryを持たないtaskも許可するため、これはoptionalな1対多relationです。

要素今回の型・property意味
PrincipalTaskCategory1件側。参照されるprimary keyを持つ
DependentTaskItem複数側。foreign keyを持つ
Foreign keyTaskItem.CategoryIdcategoryのIdを参照する
Reference navigationTaskItem.Categorytaskからcategory objectをたどる
Collection navigationTaskCategory.Taskscategoryから所属taskをたどる

CategoryIdがint?、CategoryがTaskCategory?なのは、categoryなしを nullで表せるようにするためです。C#のnullabilityはcompile時の警告だけでなく、EF Core modelでは relationとcolumnがoptionalかrequiredかを判断する情報にもなります。

JPA / Hibernateとの比較

JPAで@Entityを付けたclassとEntityManagerを使う構成に近いですが、EF Coreでは規約、attribute、 ModelBuilderの三つを組み合わせられます。今回はkeyなどの明白な部分を規約に任せ、relationと削除時の挙動を Fluent APIで明示しました。

JPA / HibernateEF Core
EntityManager / persistence contextDbContext
@Entity classmodelへ含まれるentity class
@OneToMany / @ManyToOneHasOne().WithMany()
@JoinColumnHasForeignKey()

EF CoreではIdというproperty名をprimary keyとみなすなど、規約だけでも多くを推論します。 ただし重要なrelationや削除方針を明示すると、model変更時に意図を読み取りやすくなります。

実装したコード

TaskApi.csprojとsystem SQLite

<PackageReference Include="Microsoft.EntityFrameworkCore.Sqlite.Core" Version="10.0.10" />
<PackageReference Include="SQLitePCLRaw.bundle_sqlite3" Version="2.1.11" />

通常のMicrosoft.EntityFrameworkCore.Sqliteを最初に復元したところ、同梱されるnative SQLite packageに 既知のHigh severity脆弱性警告が出ました。そのpackageには修正版が公開されていないため、native libraryを同梱しない Sqlite.Coreと、OS側のsqlite3へ接続するadapterを選びました。 このrepositoryではflake.nixがSQLiteを実行環境へ提供し、LD_LIBRARY_PATHでnative loaderへ libraryの場所を伝えます。 

SQLitePCL.Batteries_V2.Init();

application起動時にsystem SQLite providerを初期化します。NuGetだけでnative libraryが完結しない代わりに、 runtime環境が互換なsqlite3を提供する必要があります。package選択とdeployment環境の依存はセットで考えます。

Models/TaskCategory.cs

public sealed class TaskCategory
{
    public int Id { get; set; }
    public required string Name { get; set; }
    public ICollection<TaskItem> Tasks { get; } = new List<TaskItem>();
}

IdはEF Coreの規約でprimary keyになります。Nameのrequiredは、object生成時に 呼び出し側が値を設定しなければならないことをcompilerへ伝えます。Tasksはcategoryに所属する複数taskを表す collection navigationです。空collectionで初期化しているので、関連taskが0件でもnull確認なしで扱えます。

Models/TaskItem.cs

public int? CategoryId { get; set; }
public TaskCategory? Category { get; set; }

CategoryIdはdatabaseへ保存されるforeign keyです。Categoryはobject graph上で関連entityを たどるnavigationであり、同じ情報の役割が異なります。どちらもnullableなので、このtaskはcategoryなしでも存在できます。

Data/TaskDbContext.cs

public sealed class TaskDbContext(DbContextOptions<TaskDbContext> options)
    : DbContext(options)
{
    public DbSet<TaskItem> Tasks => Set<TaskItem>();
    public DbSet<TaskCategory> Categories => Set<TaskCategory>();
}

primary constructorで受け取ったDbContextOptionsをbase classへ渡します。optionsにはSQLite providerや connection stringが入ります。DbSetはentity集合へのqueryと追加・削除の入口です。property名は将来の table名にも使われます。 

entity.HasOne(task => task.Category)
    .WithMany(category => category.Tasks)
    .HasForeignKey(task => task.CategoryId)
    .OnDelete(DeleteBehavior.SetNull);

HasOneはtask側のreference navigation、WithManyはcategory側のcollection navigation、 HasForeignKeyはdatabase上の結合に使うpropertyを指定します。categoryを削除した場合はtask自体を削除せず、 nullableなCategoryIdをnullにする方針です。

Program.cs

builder.Services.AddDbContext<TaskDbContext>(options =>
    options.UseSqlite(connectionString));

AddDbContextはcontextをDIへ登録し、既定でscoped lifetimeにします。HTTP request内では同じcontextを共有し、 request終了時にDI containerがDisposeします。UseSqliteはEF Coreのrelational providerとしてSQLiteを選びます。
