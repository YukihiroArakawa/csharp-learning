DI lifetimeをコードで確認する

この課題について

  • 目安時間：30〜45分
  • 対象：02-dotnet-foundations/HostedWorker
  • 種類：AI実装＋コードレビュー

DI lifetimeは、実際のアプリケーションでサービスを登録するときに開発者が選びます。 選択を誤ると、利用者間で状態を共有したり、必要な期間より長くリソースを保持したりします。 そのため、この項目は説明だけでなくコードで挙動を確認します。

目的

同じサービスを複数回取得して、そのインスタンスがどの範囲で再利用されるかを Guid の値で確認します。確認対象は次の3種類です。

.NET DI 再利用される範囲 Springの近い概念
singleton アプリケーションのDIコンテナ全体 singleton scope
scoped 一つのスコープ内 Webでのrequest scope
transient DIから取得する1回ごと prototype scope

スコープとは

スコープは、scoped serviceを共有する範囲です。ASP.NET Coreでは通常、 HTTPリクエストごとにスコープが作られます。一方、このWorkerにはHTTPリクエストがないため、 IServiceScopeFactory.CreateScope() で境界を手動で作ります。

次の図では、singletonのAは二つのスコープから同じものが見えます。 scopedはスコープ1ではB、スコープ2ではCに分かれます。 transientは取得するたびにD、E、F、Gと新しくなります。

変更対象

  • 02-dotnet-foundations/HostedWorker/LifetimeIds.cs（新規作成）： lifetimeごとに識別用のIdを持つ3クラスを定義する
  • 02-dotnet-foundations/HostedWorker/Program.cs（編集）： 3クラスをsingleton、scoped、transientとして登録する
  • 02-dotnet-foundations/HostedWorker/Worker.cs（編集）： 二つのスコープを作り、各サービスを2回ずつ取得してログへ出す

この課題では、上記3ファイル以外を変更する必要はありません。

実装済みコード

LifetimeIds.cs

各インスタンスが生成されたときに、一度だけ新しいGuidを保持させます。 同じインスタンスなら同じId、別インスタンスなら別のIdになります。 

namespace HostedWorker;

public sealed class SingletonId
{
    public Guid Id { get; } = Guid.NewGuid();
}

public sealed class ScopedId
{
    public Guid Id { get; } = Guid.NewGuid();
}

public sealed class TransientId
{
    public Guid Id { get; } = Guid.NewGuid();
}

Program.cs

次の登録は builder.Build() より前に置きます。 AddSingleton<T> などの <T> には、登録する型を指定します。 

builder.Services.AddSingleton<SingletonId>();
builder.Services.AddScoped<ScopedId>();
builder.Services.AddTransient<TransientId>();

Worker.cs

Workerはsingletonとして動作します。scoped serviceをWorkerへ直接保持させず、 スコープを作るための IServiceScopeFactory を注入しています。

for の各周回で新しいスコープを作り、同じスコープの ServiceProvider から各サービスを2回取得します。 using var scope は各周回の終わりにスコープを破棄するため、 次の周回では新しいscopedインスタンスが作られます。 

namespace HostedWorker;

public class Worker(
    ILogger<Worker> logger,
    IServiceScopeFactory scopeFactory) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        for (var scopeNumber = 1; scopeNumber <= 2; scopeNumber++)
        {
            using var scope = scopeFactory.CreateScope();
            LogLifetimeIds(scope.ServiceProvider, scopeNumber);
        }

        while (!stoppingToken.IsCancellationRequested)
        {
            if (logger.IsEnabled(LogLevel.Information))
            {
                logger.LogInformation("Worker running at: {time}", DateTimeOffset.Now);
            }
            await Task.Delay(1000, stoppingToken);
        }
    }

    private void LogLifetimeIds(IServiceProvider services, int scopeNumber)
    {
        var singleton1 = services.GetRequiredService<SingletonId>();
        var singleton2 = services.GetRequiredService<SingletonId>();
        var scoped1 = services.GetRequiredService<ScopedId>();
        var scoped2 = services.GetRequiredService<ScopedId>();
        var transient1 = services.GetRequiredService<TransientId>();
        var transient2 = services.GetRequiredService<TransientId>();

        LogIds(scopeNumber, "singleton", singleton1.Id, singleton2.Id);
        LogIds(scopeNumber, "scoped", scoped1.Id, scoped2.Id);
        LogIds(scopeNumber, "transient", transient1.Id, transient2.Id);
    }

    private void LogIds(int scopeNumber, string lifetime, Guid firstId, Guid secondId)
    {
        logger.LogInformation(
            "Scope {ScopeNumber}, {Lifetime}: {FirstId} / {SecondId}",
            scopeNumber,
            lifetime,
            firstId,
            secondId);
    }
}

コードを読む順序

  1. LifetimeIds.cs で、インスタンスごとに異なるIdが作られることを確認する
  2. Program.cs で、同じ3クラスに異なるlifetimeが指定されていることを確認する
  3. ExecuteAsync で、スコープがループの内側で作られている理由を考える
  4. LogLifetimeIds で、同じIServiceProviderから各型を2回取得していることを追う
  5. LogIds で、値を文字列連結せず構造化ログのプレースホルダーへ渡していることを確認する

レビュー課題と完了条件

実装と機械的な検証は完了しています。次の3点をコードから読み取り、説明してください。

  1. using var scope を for の外へ移動すると、scopedのログはどう変わりますか。
  2. singletonとscopedは、同じスコープ内の2回取得だけを見ると同じ結果です。両者を区別するには、どのログを比較しますか。
  3. このWorkerへ ScopedId を直接コンストラクター注入せず、IServiceScopeFactory を注入しているのはなぜですか。
