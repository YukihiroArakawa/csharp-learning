appsettings.jsonと環境変数から設定を読む

今回の課題

  • 目安時間：20分
  • 前提：Generic Hostとコンストラクターインジェクションを読める
  • 目的：複数の設定元が一つの設定へ統合され、後の設定元が同じキーを上書きする仕組みを理解する

Codexが設定の追加と読み取りを実装します。学習者はコードと二通りの実行結果を読み、 どの設定値が最終的に選ばれるかを説明します。

Spring Bootとの対応

Spring Bootが application.properties や環境変数などを Environment へまとめるのと同様に、.NETのGeneric Hostは JSON、環境別JSON、環境変数、コマンドライン引数などを IConfiguration へまとめます。同じキーが複数にある場合は、 後から追加されたプロバイダーの値が優先されます。

実装したコード

02-dotnet-foundations/HostedWorker/appsettings.json

"Worker": {
  "Message": "appsettings.jsonからのメッセージ"
}

02-dotnet-foundations/HostedWorker/Worker.cs

public class Worker(
    ILogger<Worker> logger,
    IConfiguration configuration,
    IServiceScopeFactory scopeFactory) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var message = configuration["Worker:Message"]
            ?? throw new InvalidOperationException(
                "Worker:Message is not configured.");

        logger.LogInformation("Configured message: {Message}", message);

configuration["Worker:Message"] のコロンはJSONの階層を表します。 戻り値は設定が存在しない場合に null になり得るため、 null合体演算子 ?? で、右側の例外を代わりに使います。 Javaであれば Optional.ofNullable(value).orElseThrow(...) に近い判断です。

ログの {Message} は文字列補間ではなく構造化ログのプロパティ名です。 この点は後続の構造化ログ課題で詳しく扱います。

確認コマンド

JSONの値を使う場合：

cd 02-dotnet-foundations
timeout 3s dotnet run --project HostedWorker/HostedWorker.csproj

fishで環境変数を一時的に渡す場合：

env Worker__Message="環境変数からのメッセージ" \
  timeout 3s dotnet run --project HostedWorker/HostedWorker.csproj

timeout による終了コードはタイムアウトを示す 124 になり得ます。 今回は終了コードではなく、起動直後の Configured message を比較します。

観察結果

# 環境変数なし
Configured message: appsettings.jsonからのメッセージ

# Worker__Messageを指定
Configured message: 環境変数からのメッセージ

どちらの実行も正常に起動し、終了前まで例外は発生しませんでした。

コードリーディング課題

  1. 環境変数を指定しない場合、ログの Message には何が出ると予想しますか。
  2. Worker__Message を指定するとJSONの値ではなく環境変数の値が出るのはなぜですか。

二つの実行結果が予想どおりであり、上の2問を説明できれば完了です。
