ILoggerで構造化ログを出す

今回の課題

  • 目安時間：25分
  • 前提：DIでILogger<Worker>を受け取るコードを読める
  • 目的：ログの値を独立したフィールドとして記録し、処理単位の共通情報をscopeで付加する

CodexがJSONログとlog scopeを実装します。学習者は出力されたJSONを読み、 人間向けの文章と検索・集計用のフィールドが同時に生成される仕組みを確認します。

構造化ログとは

構造化ログでは、値を完成済みの文字列へ埋め込まず、名前付きのデータとしてloggerへ渡します。 次の{Iteration}はC#の文字列補間ではなく、message templateのフィールド名です。 

logger.LogInformation(
    "Worker heartbeat {Iteration} at {OccurredAt}",
    iteration,
    DateTimeOffset.Now);

ログ基盤は文章を表示できるだけでなく、Iteration = 3のような条件で 検索・集計できます。JavaではSLF4Jの単純な{}置換より、 key-value argumentやMDCを利用する設計に近いものです。

実装したコード

02-dotnet-foundations/HostedWorker/Worker.cs

var workerRunId = Guid.NewGuid();
using var logScope = logger.BeginScope(
    "Worker run {WorkerRunId}",
    workerRunId);

var iteration = 0;

while (!stoppingToken.IsCancellationRequested)
{
    iteration++;

    logger.LogInformation(
        "Worker heartbeat {Iteration} at {OccurredAt}",
        iteration,
        DateTimeOffset.Now);
}

BeginScopeは、以後のログへ共通情報を付ける範囲を開始します。 using varによりExecuteAsyncを抜ける際にscopeを終了します。 JavaのMDCへ処理IDを入れ、finallyで削除する使い方に近いものです。

iteration++は現在値を1増やします。Javaと同じ演算子です。 ログごとに値が変わるため、JSON上で独立した数値フィールドになっていることを確認できます。

02-dotnet-foundations/HostedWorker/appsettings.json

"Console": {
  "FormatterName": "json",
  "FormatterOptions": {
    "IncludeScopes": true
  }
}

formatterをJSONへ切り替え、BeginScopeで追加した WorkerRunIdも出力対象にします。アプリケーションコードは特定のログ保存先を知りません。

確認コマンド

cd 02-dotnet-foundations
dotnet format HostedWorker/HostedWorker.csproj --verify-no-changes
dotnet build HostedWorker/HostedWorker.csproj
timeout 3s dotnet run --no-build --project HostedWorker/HostedWorker.csproj

Worker heartbeatのJSONで、Iterationが数値として増えること、 WorkerRunIdがscope内のログで共通していることを確認します。

実際の一行JSONから、今回見るフィールドだけを整形して抜粋しています。 Iterationは1、2と数値で増え、同じ実行中のログには 同一のWorkerRunIdが含まれました。ビルドは警告・エラーともに0件でした。
